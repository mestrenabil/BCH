# Backlog — خارطة الطريق

> خارطة طريق واقعية لتطوير منصة BCH من تطبيق 3D/CSVR/شكايات إلى منصة بلدية شاملة بـ 9 مكاتب.
> كل مرحلة مستقلة قدر الإمكان ولا تكسر ما يعمل.

---

## مبدأ التطوير

1. **لا تكسر ما يعمل** — كل مرحلة تضيف فوق السابقة.
2. **التراكم التدريجي** — كل مكتب يُضاف كوحدة منفصلة + نماذج جديدة.
3. **التوحيد لاحقاً** — نظام Dossiers (المرحلة 2) يربط الكيانات دون لمسها.
4. **PostgreSQL آخراً** — SQLite كافٍ حتى تتضح الحاجة لـ PostGIS (المرحلة 12).
5. **السلامة القانونية دائماً** — راجع `docs/LEGAL_SAFETY.md` لكل ميزة إدارية.

## المرحلة 2: نظام Dossiers الموحّد ⭐

**الوصف**: طبقة توحيد فوق كل الكيانات (Intervention/Complaint/WorkOrder/StrayReport/FoodReport) — مرجع موحّد + timeline + ربط.

**النماذج الجديدة**:
- `Dossier` — مرجع `DOS-YYYY-NNNNNN`, `office`, `type`, `status` (NEW→ASSIGNED→IN_PROGRESS→INSPECTED→ACTION_REQUIRED→FOLLOW_UP→PENDING_VALIDATION→CLOSED→ARCHIVED), روابط اختيارية polymorphic-lite لكل كيان موجود.
- `DossierEvent` — timeline الحالات (`fromStatus`/`toStatus`/`changedBy`/`reason`).

**الوحدات المتأثرة**:
- جديد: `src/app/dossiers-view.tsx` + `src/app/dossiers/{list,detail,timeline}-tab.tsx`
- معدّل: `src/app/page.tsx` (navItem + render), `src/lib/store.ts` (ViewType + DossierSubTab), `src/lib/constants.ts` (DOSSIER_STATUS_*).
- جديد: `src/app/api/dossiers/route.ts` + `[id]/route.ts` + `[id]/events/route.ts`.

**معيار القبول**:
- يمكن إنشاء dossier + ربطه بكيان موجود.
- timeline يعرض تاريخ الحالات.
- قسم "Dossiers" في القائمة الجانبية.
- الكيانات الحالية تعمل دون تغيير.

## المرحلة 3: المكتب 02 — المراقبة الصحية والسلامة الغذائية 🍽️

**الوصف**: سجل المنشآت + التفتيشات + النقائص + الإجراءات التصحيحية + درجة المخاطر + البطاقات الصحية + العينات.

**النماذج الجديدة**:
- `Establishment` — منشأة (اسم، نشاط، فئة، مالك، CIN، هاتف، عنوان، GPS، إذن، فتح، حالة، فئة المخاطر).
- `EstablishmentCategory` — تصنيف النشاطات.
- `Inspection` — تفتيش (نوع: ابتدائي/دوري/مفاجئ/شكاية/معاينة/إذن/لجنة).
- `InspectionItem` — بند قائمة فحص (نظافة عامة، طاقم، أسطح، معدات، تخزين، سلسلة باردة...).
- `Finding` — نقص (minor/major/critical + درجة المخاطر).
- `CorrectiveAction` — إجراء تصحيحي + مهلة + معاينة متابعة.
- `CounterVisit` — معاينة متابعة.
- `Worker` — عامل (هوية، منشأة، مهنة).
- `HealthCard` — بطاقة صحية (رقم، إصدار، انتهاء + تنبيهات).
- `Sample` — عينة (منتج، منشأة، تاريخ، مخبر، اختبارات، نتائج، مطابقة).
- `LaboratoryResult` — نتيجة مخبرية.

**الوحدات**:
- جديد: `src/app/sanitary-view.tsx` + `src/app/sanitary/{establishments,inspections,findings,healthcards,samples}-tab.tsx`.
- جديد: مسارات API لكل كيان.
- التكامل مع `FoodReport` (بلاغ غذائي → قد يؤدي لتفتيش).

**معيار القبول**: سجل منشآت قابل للبحث + إنشاء تفتيش بقائمة فحص + نقائص + إجراءات + درجة مخاطر + بطاقات صحية بتنبيهات انتهاء.

## المرحلة 4: المكتب 03 — الماء والتطهير الصحي 💧

**الوصف**: نقاط مياه الشرب + عينات + مسابح + حوادث صرف صحي.

**النماذج الجديدة**:
- `WaterPoint` — نقطة مياه (نوع: شبكة/خزان/برج/نافورة/بئر... + GPS).
- `WaterMeasurement` — قياس (رقم عينة، نقطة، تاريخ، كلور متبقٍ، pH، حرارة، تعكّر، موصلية + اختبارات مخبرية قابلة للتهيئة).
- `Pool` — مسبح/موقع استحمام.
- `SanitationIncident` — حادث صرف (انسداد/فيضان/تصريف/ركود/بنية تحطّمت + مستوى خطر + تكليف + تدخل + تحقق).

**معيار القبول**: تسجيل نقاط مياه + قياسات + خريطة + حوادث صرف بدورة حياة.

## المرحلة 5: المكتب 04 — محاربة النواقل والتطهير والحيوانات الضالة 🐀

**الوصف**: توحيد Intervention/Campagne الحالية + مخزون المنتجات + تعميق CSVR + حالات السع/الكلاب.

**النماذج الجديدة**:
- `PestProduct` — منتج بيوسيد (مادة فعّالة، فئة، رزمة، انتهاء + تنبيهات).
- `PestStockMovement` — حركة مخزون (ENTREE/SORTIE/AJUSTEMENT + استهلاك في تدخل).
- `BiteCase` — حالة سع/عضة (متتبّعة إدارياً وصحياً — **لا تشخيص طبي آلي**).

**الوحدات المتأثرة**: ربط `Intervention` بـ `PestProduct` (موجود جزئياً في `InterventionMaterial`)، توسيع CSVR بلسع.

**معيار القباب**: مخزون منتجات بحركات + تنبيهات انتهاء/نقص + حالات سع مسجّلة.

## المرحلة 6: المكتب 05 — الجنائز والمقابر والمستودع ⚱️

**الوصف**: حالات وفاة + ملفات دفن + مستودع أموات + مقابر + نقل + نبش. كل عملية حساسة لها سجل تدقيق صارم.

**النماذج الجديدة**:
- `DeathCase` — حالة وفاة.
- `BurialDossier` — ملف دفن.
- `MorgueRecord` — سجل المستودع.
- `Cemetery` — مقبرة.
- `CemeteryPlot` — قسم/قبر.
- `CorpseTransport` — نقل جثمان.
- `ExhumationDossier` — ملف نبش.

> ⚠️ كل إذن (دفن/نبش/نقل) يتطلب مصادقة يدوية + حقول قانونية قابلة للتهيئة. راجع `docs/LEGAL_SAFETY.md`.

**معيار القبول**: دورة حياة كاملة للوفاة→الدفن، سجل المستودع، إدارة المقابر.

## المرحلة 7: المكتب 06 — المحافظة على البيئة 🌳

**الوصف**: ملفات بيئية + مشاريع + تلوث + نفايات + مواقع طبيعية + حملات تحسيس.

**النماذج الجديدة**:
- `EnvironmentalDossier` — ملف بيئي.
- `PollutionIncident` — تلوث (هواء/ماء/تربة/ضجيج/روائح/دخان/غبار).
- `WasteBlackSpot` — نقطة رمي عشوائي + تكرار + تاريخ تدخلات.
- `EnvironmentalInspection` — تفتيش بيئي (احتمالية × خطورة × تعرّض = درجة مخاطر داخلية).
- `NaturalSite` — موقع طبيعي/تراثي (GIS).
- `AwarenessCampaign` — حملة تحسيس.

**المنجز**: ملفات بيئية مرتبطة تلقائياً بـ`Dossier` موحّد وسجل زمني، آجال للمعاينة والمتابعة، درجات مخاطر، وربط بالمستندات، إضافة إلى طبقات GIS القائمة للتلوث والنفايات والمواقع والملفات البيئية.

**المتبقي**: نموذج `EnvironmentalInspection` مستقل عند اعتماد استمارة تفتيش رسمية قابلة للتهيئة، مع عدم اختراع مرجع قانوني أو قرار إداري آلي.

## المرحلة 12: ترحيل PostgreSQL/PostGIS + نشر VPS 🚀

**قاعدة البيانات**:
- `DATABASE_URL` → PostgreSQL.
- `prisma migrate` (بدل `db:push`).
- الإحداثيات → `geometry(Point, 4326)` + فهارس GIST.
- استعلامات المسافة → `ST_DWithin`/`ST_Distance`.

**النشر**:
- Ubuntu VPS + Nginx (HTTPS) + PM2 + PostgreSQL/PostGIS.
- `storage/` و DB خارج الحاوية.
- نسخ احتياطي دوري (cron: JSON + DB dump + storage/).

**معيار القبول**: تطبيق يعمل على PostgreSQL + PostGIS queries + نشر إنتاجي مستقر.
