# Legal Safety — قواعد السلامة القانونية ⚠️

> هذه الوثيقة تضع حدوداً واضحة بين الدعم التقني والقرار الإداري/القانوني.
> **المنصة أداة دعم قرار، ليست سلطة قرار.**

---

## 1. القاعدة الأساسية

> **لا تخترع قوانين مغربية، أرقام مراسيم، قرارات وزارية، مواد قانونية، أو صلاحيات بلدية.**

لا تضع في الكود أو الواجهة:
- أرقام قوانين أو مراسيم مختلقة (مثل "المادة 12 من القانون 60.09").
- نصوص قانونية كأنها نصوص رسمية.
- صلاحيات إدارية غير متحقّق منها.
- عتبات قانونية (مثل "درجة المخاطر > 70 = إغلاق إلزامي").

**إذا لم تكن متأكداً من مرجع قانوني، لا تذكره. اعرض "Base juridique à vérifier".**

---

## 2. الإجراءات الإدارية الحساسة

الإجراءات التالية لها عواقب قانونية ولا يجوز تنفيذها آلياً:

| الإجراء | فرنسي | السياق |
|---|---|---|
| الإغلاق الإداري | Fermeture administrative | إغلاق منشأة مخالفة |
| المصادرة | Saisie | مصادرة منتجات فاسدة |
| الإتلاف | Destruction | إتلاف مواد غير صالحة |
| التعليق | Suspension | تعليق رخصة/نشاط |
| إذن الدفن | Autorisation d'inhumation | تصريح بدفن متوفى |
| نبش القبر | Exhumation | نقل رفاة |
| عقوبة إدارية | Sanction administrative | غرامة/توقيف |
| الإنذار | Mise en demeure | إشعار رسمي |

### القاعدة
> **كل إجراء من هذا النوع يتطلب:**
> 1. **مصادقة يدوية** من الموظف المختص (لا تنفيذ آلي).
> 2. **مرجع قانوني موثّق** (إذا توفّر).
> 3. **سجل تدقيق** بمن أنجز ومتى ولماذا.
> 4. **وثيقة داعمة** مرفقة عند الحاجة.

---

## 3. الحقول القابلة للتهيئة (Configurable Legal Fields)

لكل إجراء إداري، استخدم هذا النمط (لا تثبّت القيم في الكود):

```typescript
// في النموذج/الكيان:
{
  // ... حقول العملية ...
  legalReference: String    // "" افتراضياً — مرجع قانوني اختياري
  legalArticle:   String    // "" — مادة محددة إن وُجدت
  competentAuthority: String // "" — الجهة المختصة (العمالة، الرئيس، إلخ)
  decisionType:   String    // نوع القرار المتخذ
  validationStatus: String  // PENDING/APPROVED/REJECTED
  validatedBy:    String?   // من صادق (userId)
  validatedAt:    DateTime? // متى
}
```

### منطق العرض
```typescript
function renderLegalBasis(record) {
  if (record.legalReference && record.validationStatus === 'APPROVED') {
    return `📖 ${record.legalReference}`  // عرض المرجع
  }
  return '⚠️ Base juridique à vérifier'   // الأساس القانوني قيد التحقق
}
```

**في الواجهة**: اعرض شارة صفراء/برتقالية "الأساس القانوني قيد التحقق" عندما لا يكون مرجع موثّق مهيّأً.

## 4. درجة المخاطر الصحية (Sanitary Risk Score)

### ما هي عليه
درجة بين **0 و100** تُحسب من نتائج التفتيش (نقائص minor/major/critical).

### ما هي ليست عليه
> **الدرجة أداة دعم قرار تقنية، ليست قراراً قانونياً.**

- لا تربط الدرجة آلياً بإجراء قانوني (لا "درجة > 70 = إغلاق").
- لا تعرضها كأنها تقدير قانوني رسمي.
- اعرضها كـ "مؤشر داخلي" مع تفسير واضح لمنطلقها.

### النمط المعتمد
```typescript
// عرض:
"مؤشر المخاطر الداخلي: 72/100 — يحتاج معاينة متعمّقة"
// لا:
"مؤشر المخاطر: 72 → إغلاق إلزامي"  // ❌ ممنوع
```

---

## 5. العتبات والحدود

### لا تثبّت عتبات قانونية
لا تضع في الكود قيم مثل:
```typescript
// ❌ ممنوع:
const CLOSURE_THRESHOLD = 70  // "إغلاق عند درجة 70"
const EXPIRY_FINE_AMOUNT = 500  // "غرامة 500 درهم"
const INSPECTION_FREQUENCY_DAYS = 90  // "تفتيش كل 90 يوماً (قانوني)"
```

### بدلاً من ذلك: حقول قابلة للتهيئة
```typescript
// ✅ مقبول (قابلة للتهيئة من إعدادات الجماعة):
// في CommuneSettings أو جدول إعدادات مستقل:
{
  riskThresholds: { warning: 50, critical: 75 },  // إعدادات داخلية
  inspectionFrequency: { high: 90, medium: 180, low: 365 }  // أيام (إرشادي)
}
```

**وضّح دائماً** أن هذه العتبات إعدادات داخلية، لا حدوداً قانونية.

---

## 6. المراجع القانونية — ما يجب فعله

### عند الحاجة لمرجع قانوني
1. **لا تخمن.** إذا كان المستخدم يطلب ميزة تستلزم مرجعاً قانونياً (مثل "أضف حقل المادة القانونية للتفتيش"):
   - أضف الحقل **فارغاً** (`legalReference: String @default("")`).
   - اعرض **"Base juridique à vérifier"** كقيمة افتراضية.
   - اترك التهيئة للمستخدم/الجهة المختصة.

2. **لا تنسخ من الإنترنت** نصوصاً قانونية كأنها موثّقة. قد تكون قديمة أو غير دقيقة.

3. **إذا قدّم المستخدم مرجعاً صريحاً** (رقم قانون + مادة + نص)، يمكن وضعه في حقل قابل للتهيئة مع توثيق المصدر.

### المراجع الخارجية الموصى بها
المراجع القانونية المغربية الرسمية تُوجد في:
- بوابة قانون.gov.ma
- الجريدة الرسمية (bulletin officiel)
- بوابة الأمانة العامة للحكومة

> لا تدمج هذه تلقائياً — يجب التحقق اليدوي.

## 7. سجل التدقيق للقرارات الحساسة

لكل قرار إداري (إغلاق، مصادرة، إذن دفن...)، يجب أن يحتوي `ActivityLog` على:

| الحقل | القيمة |
|---|---|
| `action` | `VALIDATE` / `REJECT` / `CLOSURE` / `SEIZURE`... |
| `entityType` | الكيان المعني |
| `entityId` | معرّف السجل |
| `details.decisionType` | نوع القرار |
| `details.legalReference` | المرجع القانوني (أو فارغ) |
| `details.reason` | سبب القرار |
| `details.validatedBy` | userId الموظف |
| `details.timestamp` | ISO timestamp |

> **القرارات الإدارية لا تُمحى بصمت.** استخدم نسخ (versioning) أو أرشفة بدل الحذف المدمر.

---

## 8. قائمة فحص السلامة القانونية

عند إضافة ميزة تتعلق بإجراءات إدارية:
- [ ] لا توجد قوانين/مراسيم مختلقة في الكود أو الواجهة.
- [ ] لا توجد عتبات قانونية ثابتة (استخدم حقول قابلة للتهيئة).
- [ ] لا يُنفّذ الإجراء آلياً بناءً على خوارزمية فقط (تتطلب مصادقة يدوية).
- [ ] درجة المخاطر (إن وُجدت) موسومة كـ "مؤشر داخلي".
- [ ] الحقول القانونية (`legalReference`, `competentAuthority`...) فارغة افتراضياً.
- [ ] عرض "Base juridique à vérifier" عند غياب المرجع.
- [ ] `ActivityLog` يسجّل القرار بمن/متى/لماذا.
- [ ] لا حذف مدمر للقرارات (أرشفة/versioning).

---

## 9. ملاحظة حول تكاملات الأنظمة الخارجية

### نظام روخاس (Rokhas)
الـ spec يذكر حقلاً اختيارياً `rokhas_reference`. القاعدة:
> **لا تدّع تكاملاً مباشراً مع Rokhas ما لم يُنفّذ تكامل API فعلي.**

- اترك الحقل كمرجع نصي فقط (`rokhasReference: String?`).
- لا تكتب "متزامن مع Rokhas" أو "مُستورد من Rokhas".
- التكامل الفعلي يتطلب وثائق API رسمية + اتفاقية + مصادقة.

### أنظمة أخرى (Guichet Unique، Wali، إلخ)
نفس القاعدة: لا ادّعاء تكامل دون تنفيذ موثّق.
