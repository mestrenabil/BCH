# خطة: توثيق معماري + توسيع تدريجي لمنصة BCH

## السياق
المستودع الحالي تطبيق شغّال بكامل (23 وحدة، 28 جدول Prisma، مصادقة مخصصة، i18n، خرائط Leaflet، PWA) لكن بلا توثيق معماري صفر، ولا مفهوم "مكاتب"، ولا نظام dossiers موحّد. الـ spec يطلب منصة بـ 9 مكاتب + PostgreSQL/PostGIS + dossiers. قرار المستخدم: **توثيق + توسيع تدريجي دون كسر ما يعمل**.

## ما سأنفّذه الآن (مرحلة التأسيس — لا أكسر شيئاً)

### 1️⃣ `AGENTS.md` (جذر المستودع)
وثيقة موجّهة للوكلاء/المطوّرين، تشمل:
- غاية التطبيق + السياق المغربي (عمالة سلا، قسم حفظ الصحة)
- البنية الحالية (Next.js 16 App Router، Prisma+SQLite، Zustand، Leaflet، i18n عربي/فرنسي)
- منظومة المكاتب التسعة المستهدفة + خريطة كل مكتب للوحدات الموجودة (Lutte antivectorielle=Intervention/Campagne, Réclamations=Complaint, إلخ)
- اصطلاحات الكود (Arabic comments، `statut` للفرنسية، `reference` فريدة، `commune` كمحور تنظيمي، نمط API `requireAuth`+`getScopedCommuneFilter`)
- قواعد الأمان (RBAC بـ3 أدوار، rate limiting عمومي، honeypot، path-traversal safe storage، لا أسرار في الكود)
- متطلبات RTL/i18n (القاموس المركزي في `i18n.ts`، `dir="rtl"`، لا تكرار مكوّنات للترجمة)
- قاعدة السلامة القانونية (لا اختراع قوانين، حقول `legal_reference` قابلة للتهيئة، لا قرارات إدارية آلية)
- أوامر الاختبار (`npx next build`، `npx tsc --noEmit`، `npm run db:push`)
- تعريف "الإنجاز": البناء ناجح + TS نظيف + المسارات تعمل + RTL سليم

### 2️⃣ `docs/ARCHITECTURE.md`
- نظرة عامة على المعمارية (SPA client-side مع `currentView` switch، API routes RESTful، Prisma singleton)
- مخطط الطبقات (UI → API → Auth → Prisma → SQLite/Storage)
- نمط العرض الديناميكي (`dynamic(() => import(...), { ssr: false })`)
- منظومة الجلسات (cookie `3d_session_token`، scrypt، throttling)
- الفلترة الترابية (`commune` → `getScopedCommuneFilter` → `canAccessCommune`)
- التخزين المبني على الملفات (`storage/` مع وحدات `*-storage.ts`)
- خريطة طريق: SQLite → PostgreSQL/PostGIS (متى ولماذا)
- مكوّنات قابلة لإعادة الاستخدام (`src/components/ui/` shadcn-style)

### 3️⃣ `docs/DATA_MODEL.md`
- جدول كامل لكل النماذج الـ28 مع الحقول الرئيسية وقيم `statut`/`source`/`priority` المتاحة
- خريطة العلاقات (WorkOrder↔Complaint↔Intervention، StrayReport↔CaptureMission، FoodReport↔FoodReportPhoto)
- نمط المراجع (`PL-`, `OT-`, `SIG-CSVR-`, `SIG-FOOD-`)
- الفجوة: لا `enum` Prisma (كلها `String` مع تعليقات)، لا نموذج `Office`، لا نظام dossiers موحّد
- مقترح التوحيد: دورة حياة dossiers عامة (NEW→ASSIGNED→...→ARCHIVED) كطبقة فوق النماذج الحالية
- ملاحظة PostGIS: الإحداثيات حالياً `Float?` — خطة الترقية لـ `geometry(Point, 4326)`

### 4️⃣ `docs/SECURITY.md`
- RBAC (admin/responsable/agent + scope commune)
- المصادقة (scrypt، throttling 5/15د، جلسة 24س)
- المسارات العمومية (`/api/public/*` مع `consumePublicRateLimit` + honeypot `website`)
- التحقق من المدخلات + sanitize + path-traversal safe file serving
- رفع الملفات (حجم/نوع، `flag:'wx'`، rollback عند فشل DB)
- سجل التدقيق (`ActivityLog`، `entityType`/`action` نص حر)
- الترقية الموصى بها: CSRF tokens، helmet headers، CSP، rate-limit per-user على API الداخلية
- قاعدة: لا حذف مدمر للسجلات الإدارية (soft delete / archive)
