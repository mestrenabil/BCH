# المنصة المندمجة لتدبير قسم الوقاية وحفظ الصحة

منصة داخلية لتدبير عمليات الوقاية وحفظ الصحة، وتشمل حملات مكافحة القوارض والحشرات والتطهير، الشكايات، أوامر العمل، التطبيق الميداني، الحيوانات الشاردة، المراقبة الصحية، البيئة، الماء، التقارير، ونظام المعلومات الجغرافية.

## المتطلبات

- Node.js 22 LTS موصى به للتطوير والاختبارات وCI.
- الحد الأدنى لتشغيل Next.js هو Node.js 20.9.
- PostgreSQL 15 أو أحدث للإنتاج.
- npm 10 أو أحدث.

## قاعدة البيانات

يستخدم الإصدار الحالي Prisma مع PostgreSQL. ملف `db/custom.db` هو نسخة SQLite القديمة ومصدر احتياطي للترحيل، ولا يُستخدم كقاعدة تشغيل للإنتاج.

- مصدر المخطط: `prisma/schema.prisma`.
- عدد النماذج الحالية: 98 نموذجاً.
- migrations PostgreSQL موجودة في `prisma/migrations/`.
- لا تستخدم `prisma db push` في الإنتاج.
- لا تستخدم `prisma migrate reset` على قاعدة تحتوي بيانات حقيقية.

## الإعداد المحلي

1. انسخ `.env.example` إلى `.env`.
2. عيّن `DATABASE_URL` إلى قاعدة PostgreSQL محلية أو staging، ولا تحفظ كلمة المرور في Git.
3. ثبّت الاعتماديات عبر `npm ci`.
4. ولّد Prisma Client عبر `npx prisma generate`.
5. طبّق migrations على قاعدة فارغة أو staging عبر `npx prisma migrate deploy`.

## التشغيل

للتطوير على المنفذ الافتراضي `3000`:

```bash
npm run dev
```

للتطوير على المنفذ `3003`:

```bash
npx next dev -p 3003 -H 0.0.0.0
```

للإنتاج:

```bash
npm run build
npm start
```

تعمل نسخة الإنتاج الحالية على `127.0.0.1:3002`، وتُعرض للمستخدمين عبر Nginx أو reverse proxy.

## ترحيل الحسابات من SQLite

بعد تطبيق migrations على PostgreSQL، يمكن نقل حسابات المستخدمين فقط مع الحفاظ على كلمات المرور المشفّرة:

```bash
npm run db:import-users
```

يقرأ السكربت `db/custom.db` بوضع القراءة فقط، ويرفض العمل إذا كان `DATABASE_URL` لا يشير إلى PostgreSQL. لا يحذف أو يعدّل قاعدة SQLite، ويتجاوز أسماء المستخدمين الموجودة مسبقاً.

يجب تنفيذ ترحيل باقي البيانات عبر خطة منفصلة مع نسخة احتياطية والتحقق من أعداد السجلات قبل وبعد النقل.

## التهيئة الأولى والمستخدمون

يحتاج إنشاء المسؤول الأول إلى `INITIAL_SETUP_TOKEN` و`INITIAL_ADMIN_USERNAME` و`INITIAL_ADMIN_PASSWORD` في ملف البيئة. يجب استعمال كلمة مرور قوية وعدم وضع هذه القيم في Git.

لإنشاء حساب ميداني، أنشئ العون أولاً ثم أنشئ مستخدماً بدور `agent` واربطه بملف العون. لا يرى حساب العون إلا أوامر العمل المسندة إليه.

لا تستخدم `npm run db:seed:2025` في الإنتاج؛ فهو مخصص لبيانات تجريبية في التطوير أو staging.

## المراقبة والنسخ الاحتياطي

- افحص حالة الخدمة عبر `GET /api/health`؛ يعيد `200` عند توفر قاعدة البيانات و`503` عند تعذرها.
- أنشئ نسخة SQLite قبل الترحيل عبر `node scripts/backup-before-postgres.js`.
- ينشئ مسؤول النظام نسخة JSON عبر `GET /api/backup`.
- احتفظ بنسخة JSON مع نسخة مستقلة من مجلد `storage/`، لأنه يحتوي الوثائق والصور وأدلة التنفيذ.
- راجع سجل النشاط لمتابعة إنشاء وتحديث وحذف العمليات والوثائق والأدلة.

## البريد للشكايات العامة

تطلب صفحة `/signaler` بريد المشتكي وترسل إليه مرجع التتبع عند توفر إعدادات SMTP. عيّن `SMTP_HOST` و`SMTP_PORT` و`SMTP_SECURE` و`SMTP_USER` و`SMTP_PASSWORD` و`SMTP_FROM` في ملف البيئة. إذا لم تُضبط هذه القيم، يبقى البلاغ محفوظاً ويظهر المرجع للمبلغ.

## النشر على VPS

1. يفضّل إنشاء مستخدم تشغيل مستقل؛ إعداد الخادم الحالي يستخدم حساب النشر المعرّف في `SERVER_USER`.
2. استنسخ المستودع عبر SSH Deploy Key إلى `/var/www/BCH`.
3. أنشئ ملف `/var/www/BCH/.env` بصلاحيات `600`، ولا ترفعه إلى Git.
4. اجعل PostgreSQL متاحاً على `127.0.0.1` أو شبكة خاصة فقط، ولا تعرض المنفذ `5432` على الإنترنت.
5. نفّذ `npm ci` ثم `npx prisma migrate deploy` ثم `npm run build`.
6. شغّل التطبيق عبر PM2 باستخدام `ecosystem.config.cjs`.
7. اضبط Nginx لتمرير الدومين إلى `http://127.0.0.1:3002`.
8. فعّل HTTPS عبر شهادة Let's Encrypt.

يستخدم `scripts/deploy-production.sh` migrations versioned بدلاً من `db push`، ولا ينفّذ استيراد SQLite تلقائياً.

## GitHub Actions

يعمل Workflow الموجود في `.github/workflows/deploy-production.yml` عند الدفع إلى الفرع `main`. يتحقق من البناء والاختبارات ويطبق migrations على قاعدة CI مؤقتة، ثم ينشر إلى VPS بعد نجاح التحقق.

يجب إعداد أسرار GitHub التالية دون وضعها في الملفات:

- `SERVER_HOST`
- `SERVER_USER`
- `SERVER_SSH_KEY`

الأسرار الاختيارية:

- `SERVER_PORT`، والقيمة الافتراضية `22`.
- `SERVER_KNOWN_HOSTS`، وهو الخيار الآمن الموصى به لتثبيت بصمة الخادم.

تُحفظ `DATABASE_URL` الإنتاجية حصراً في ملف `/var/www/BCH/.env` على الخادم.

## الأمان

- لا ترفع `.env` أو `.env.postgres-staging` أو `db/custom.db` أو `backups/` أو `storage/` إلى GitHub.
- استخدم HTTPS دائماً.
- PostgreSQL لا يجب أن يكون مكشوفاً على الإنترنت.
- غيّر كلمات مرور التهيئة والحسابات الافتراضية قبل الإطلاق.
- طبّق الصلاحيات في الخادم، وليس في الواجهة فقط.
