# المنصة المندمجة لتدبير قسم الوقاية وحفظ الصحة

منصة داخلية لتدبير حملات مكافحة القوارض والحشرات والتطهير، مع الشكايات، أوامر العمل، التطبيق الميداني، والأدلة المصورة.

## المتطلبات

- Node.js 20.9 أو أحدث
- قاعدة SQLite افتراضياً، أو `DATABASE_URL` يشير إلى قاعدة Prisma مدعومة

## الإعداد والتشغيل

1. انسخ `.env.example` إلى `.env` وعيّن قيماً قوية لمتغيرات التهيئة الأولية.
2. ثبّت الاعتماديات عبر `npm install`.
3. طبّق مخطط قاعدة البيانات عبر `npm run db:push`.
4. للتطوير: `npx next dev -p 3003`.
5. للإنتاج: شغّل `npm run build` ثم `npm start`.

تستمع نسخة الإنتاج افتراضياً على المنفذ `3000`. يمكن تغيير المنفذ بإضافة `-p` إلى أمر `npm start`.

## التهيئة الأولى

استخدم `INITIAL_SETUP_TOKEN` الموجود في `.env` عند تهيئة حساب المسؤول. لا تشغّل التهيئة التجريبية في الإنتاج: اترك `ALLOW_DEMO_SEED=false`.

لإنشاء حساب ميداني، أنشئ العون أولاً ثم أنشئ مستخدماً بدور `agent` واربطه بملف العون؛ لا يرى هذا الحساب إلا أوامر العمل المسندة إليه.

## المراقبة والنسخ الاحتياطي

- افحص حالة الخدمة عبر `GET /api/health`؛ يعيد `200` عندما تكون القاعدة متاحة و`503` عند تعذرها.
- ينشئ مسؤول النظام نسخة JSON من `GET /api/backup`. تشمل النسخة أوامر العمل، الشكايات، الحملات، وسجل العمليات.
- احتفِظ مع نسخة JSON بنسخة من مجلد `storage/` لأنه يحتوي الملفات الخاصة: الوثائق وأدلة التنفيذ المصورة.
- تابع صفحة سجل النشاط لمراجعة إنشاء أوامر العمل، تغيير حالتها، ورفع أو حذف أدلة التنفيذ.

## إشعار البريد للشكايات العامة

تطلب صفحة `/signaler` بريد المشتكي وترسل إليه مرجع التتبع بعد تسجيل البلاغ. اضبط متغيرات `SMTP_HOST` و`SMTP_PORT` و`SMTP_SECURE` و`SMTP_USER` و`SMTP_PASSWORD` و`SMTP_FROM` في `.env`. ملف `.env` الحالي لا يحتوي على إعدادات SMTP؛ لذلك سيبقى البلاغ مسجلاً وسيظهر المرجع على الشاشة إلى حين إدخال بيانات خادم البريد.

## النشر الآمن

- استخدم قاعدة بيانات ومجلد `storage/` دائمين خارج حاوية التطبيق المؤقتة.
- لا ترفع ملف `.env` أو النسخ الاحتياطية أو مجلد `storage/` إلى مستودع عام.
- ضع المنصة خلف HTTPS، وغيّر كلمات مرور التهيئة والمشرف قبل الإطلاق.
